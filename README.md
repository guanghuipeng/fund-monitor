# 基金监控与止盈提醒（fund-monitor）

一个**零第三方依赖**的基金监控工具，可本机运行，也可用 GitHub Actions 全自动运行。每个交易日抓取基金净值、指数估值和评级，按规则判断：

- **低估** → 提醒分批买入；
- **高估** → 提醒分批减仓；
- **从高估区峰值回撤达到阈值** → 提醒卖出剩余仓位（回撤止盈，不要求你猜最高点）；
- 生成一个自包含的 HTML 面板，并把触发信号推到 GitHub Issue / 邮箱（也可选 Server酱 / PushPlus）。

> 只提醒，不自动交易，不接券商账户。输出不构成投资建议。

## 1. 两套“星级”，别混用

| 名称 | 来源 | 方向 | 用途 |
|---|---|---|---|
| **市场星级** `market_star` | 公众号文章（螺丝钉 / ETF拯救世界等） | **5 星最便宜，1 星最贵** | 全市场温度计，作参考 |
| **指数修正星级** | 该指数自己的估值星级 + 3 年价格回撤（中证800 的估值星级由成分指数加权） | **5 星最便宜，1 星最贵** | **中证800 买卖的主信号** |
| **晨星评级** `morningstar` | 天天基金 F10 / 晨星 | **5 星基金质量最好** | 只展示，作为质量门槛，不是估值信号 |

面板里会分别标注。把“5 星基金”当成“高估”是错的；把全市场星级直接套到单只指数上也是错的。

### 1.1 指数修正星级（中证800 用这个）

```text
修正星级 = min(估值星级, 价格星级)
```

- **估值星级**：该指数全历史综合分位 `0.6*PE分位 + 0.4*PB分位` 映射到星级，

  | 全历史分位 | ≤10% | 20% | 40% | 60% | 80% | 100% |
  |---|---:|---:|---:|---:|---:|---:|
  | 估值星级 | 5.0 | 4.8 | 4.0 | 3.0 | 2.0 | 1.0 |

  **中证800 例外**：先分别算沪深300、中证500 的估值星级，再按 75% / 25% 加权。
  不能先把两者的 PE/PB 水平混合再取分位——分位不是线性的，混合后的分位会被
  权重更大、但当时并不便宜的一侧带偏（2008-03 就是这样误判的）。

- **价格星级**：相对过去 3 年最高点的回撤，

  | 距 3 年高点 | ≥-5% | -10% | -20% | ≤-30% |
  |---|---:|---:|---:|---:|
  | 价格星级 | 3.8 | 4.2 | 4.5 | 5.0 |

两星取较小值。对中证500/沪深300，**4.8 星 = 估值分位 ≤20% 且价格距 3 年高点 ≤-26%**；中证800 的估值门槛是成分加权估值星级 ≥4.8，价格门槛相同。只有估值便宜、价格也跌下来，才算真正的买点；2021 年中证500 价格到顶但 PE 分位仍低的情况会被价格星级挡住。

## 2. 快速开始

环境：Python 3.9+（Windows / macOS / Linux 均可），无需安装任何第三方包。

```bash
cd fund-monitor

python fund.py init --demo        # 生成配置 + 3 只演示基金
python fund.py check --dry-run    # 抓数据、算信号、不推送
python fund.py report --open      # 打开 reports/dashboard.html
```

输出示例：

```
161725 招商中证白酒指数(LOF)A：净值 0.5406（2026-10-20），估值分位 14%
000961 天弘沪深300ETF联接A：净值 1.5067（2026-10-20），估值分位 45%
110022 易方达消费行业股票：净值 2.799（2026-10-20），估值分位 --
```

换成你自己的基金：

```bash
python fund.py add 161725                    # 自动识别类型/跟踪标的
python fund.py add 110022 --kind active      # 主动基金可显式指定
python fund.py add 000961 --alias 沪深300联接
python fund.py list
python fund.py remove 000961
```

`add` 会自动抓名称、基金类型、跟踪标的，并尝试映射到蛋卷指数估值。主动基金没有实时估值，工具会用净值位置指标代替。

## 3. 规则（可在 config.json 改）

### 3.1 买入提醒

| 条件 | 提醒 |
|---|---|
| 指数估值分位 ≤ 20%，且 PB 分位 ≤ 30%（或蛋卷标记 low） | 分批买入 / 定投 |
| 指数估值分位 ≤ 10% | 加大定投额 |
| 主动基金：3 年净值分位 ≤ 15%，且距 250 日高点 ≤ -20%，晨星 ≥ 3 星 | 加入观察，可小额定投 |
| 主动基金：3 年净值分位 ≤ 5%，且距 250 日高点 ≤ -30% | 分档建仓，加大定投 |
| 晨星 1–2 星 | 降级为“控制仓位/换同指数更优产品” |
| 市场星级 < 3.5 | 暂缓买入，等待更好位置 |
| 市场星级 ≥ 4.5 | 买入提醒优先级提高（面板显示） |

估值分位 = `0.6 * PE 百分位 + 0.4 * PB 百分位`（缺一项则用另一项）。数据来自蛋卷，覆盖 63 个常见宽基/行业/海外指数。

### 3.2 卖出 / 止盈状态机

每只基金在 `data/state.json` 记录：所处区域、高估区峰值、已执行档位、冷却期。

| 档位 | 触发 | 动作 |
|---|---|---|
| **T1 高估区** | 指数估值分位 ≥ 80%（市场星级 < 3.5 时收紧到 75%）；主动基金 3 年净值分位 ≥ 90% 且距 250 日高点 ≤ 5% | 减仓约 1/3，开始记录峰值 |
| **T2 极度高估** | 指数估值分位 ≥ 90%；主动基金 3 年净值分位 ≥ 97% | 再减约 1/3 |
| **T3 回撤止盈** | 从进入高估区后的峰值回撤达到阈值：宽基 8% / 行业 10% / 主动 12%（可单只覆盖） | 卖出剩余，进入“止盈后观望” |

细节：

- 进入高估区当天如果已经极度高估，会一次性提示 T1+T2（约 2/3），避免拖两天。
- 高估区内创新高只更新峰值，不重复推 T1。
- 同一档位冷却 5 个交易日；`state.json` 做幂等，不会每天刷屏。
- T3 后不马上重新买入。等估值/净值分位回落到 70% 以下并持续 5 个交易日，且距旧峰值至少 -8%，才重新武装。
- 指数基金可选择盘中用实时指数点位跟踪峰值（`--intraday`），主动基金只能用最新净值。
- **不会**因为“跌了 20%”就自动喊止损；那和低吸信号会打架。深度回撤只在买入规则里体现。

### 3.3 为什么用回撤止盈

历史数据里，60 日涨幅超过 15% 之后的回撤分布很宽（-2% 到 -40%）。预测顶部不可靠，但“进入高估区 + 从峰值回撤 X% 就执行”是可复盘、可执行的纪律。阈值按品种分档，避免高波动行业被 8% 的紧止损反复扫出。

### 3.4 中证800 单指数策略（v3.2，线上主规则）

每轮熊市准备 20 万，按指数自己的修正星级执行：

| 档位 | 触发 | 动作 |
|---|---|---|
| **T1 建仓** | 修正星级 ≥ 4.8（估值分位 ≤20% 且较 3 年高点 ≤-26%） | 按 1 年回撤深度买：≤-60% 投 2/3，≤-40% 投 1/2，否则 1/3 |
| **T2 加仓** | 价格 ≤ T1×0.90；或 T1 时 1 年回撤 ≤-40% 且 120 日线转上、现价站上 120 日线；或价格始终不到时，T1 后 ≥60 天、年线向上且现价高于年线 8% | 买剩余现金的一半 |
| **T3 加仓** | 价格 ≤ T1×0.80；或 250 日线转上且现价站上年线 | 买最后剩余现金 |
| **崩盘过滤** | 1 年回撤 ≤-30% 且现价低于年线 15% | 暂停 T2/T3 的价格触发；回到年线 85% 以上或趋势确认后恢复 |
| **S1 首卖** | 全历史估值分位 ≥60% | 卖出 1/3 |
| **S2 清仓** | 全历史估值分位 ≥63% | 卖出剩余 2/3 |
| **强趋势** | 现价 > 1.30×250 日线 | 剩余 2/3 不按 63% 卖，改 12% 移动止盈 |
| **保险** | 本轮最大浮盈 ≥40%，且从本轮高点回撤 ≥10%，且年线向上，且尚未 S1 | 全部卖出；强趋势中暂不触发 |

- 首笔不固定 1/3：熊市跌得越深，第一笔越大，避免在真正底部只买到很小仓位。
- 没买满的现金放货币基金，不追高；T2/T3 的趋势确认用于避免 2022 年那种熊市反弹。
- V 型底补仓只用来处理“跌幅不深、但趋势已经转上”的浅底（如沪深300 2018），8% 的年线距离用于挡住 2023 年中证500 那种熊市反弹。
- 崩盘过滤：1 年回撤 ≤-30% 且现价低于年线 15% 时，T2/T3 的**价格触发**暂停；等价格回到年线 85% 以上，或出现趋势确认/V 型补仓时恢复。用来避免 2008 年那种单边下跌中越跌越买、过早打光资金。
- 卖出**不看星级**（星级是买入侧指标），只看全历史分位、移动止盈线和保险线。
- 线上网页与推送使用 `v3_rule.py`，回测使用 `rule_validation.py --v3`，两边是同一套参数（v3.2）。
- 这套规则已在沪深300、中证500、中证800 三个宽基的全部可用历史上验证，详见 9.3。
- 命令：`python index_watch.py` 看今天几星、v3.2 当前该做什么。

## 4. 配置文件

`config.json` 由 `init` 生成，关键字段：

```json
{
  "push": {
    "enabled": false,
    "provider": "serverchan",
    "serverchan_key": "",
    "pushplus_token": ""
  },
  "run": {
    "weekly_summary_weekday": 5,
    "buy_cooldown_days": 10,
    "cooldown_days": 5,
    "rearm_days": 5,
    "article_max_age_days": 7,
    "index_watch_push": false
  },
  "thresholds": {
    "buy": { "low_pct": 0.20, "deep_low_pct": 0.10, "pb_guard": 0.30 },
    "sell": { "high_pct": 0.80, "extreme_pct": 0.90 },
    "trailing": { "broad_index": 0.08, "sector_index": 0.10, "active": 0.12 },
    "rearm_val_pct": 0.70,
    "rearm_drawdown": -0.08
  },
  "funds": [
    {
      "code": "161725",
      "alias": "白酒",
      "kind": "index",
      "index_code": "SZ399997",
      "enabled": true,
      "cost": null,
      "shares": null,
      "trailing_drawdown": null
    }
  ],
  "network": { "proxy": "" }
}
```

- `trailing_drawdown` 单只覆盖，例如白酒想用 12% 就填 `0.12`。
- `cost` / `shares` 预留：都填了面板会显示持仓盈亏；不填不影响信号。
- `index_code` 可手动指定蛋卷代码（`SZ399997`、`SH000300`、`HKHSTECH` 等），优先级最高。
- `weekly_summary_weekday` 用 ISO 星期：1=周一 … 5=周五。
- `index_watch_push=true`：即使当天没有基金信号，也推一份“中证800 / 中证500 / 沪深300 / 全市场 星级日报”；有信号时星级表会自动附在信号推送后面。
- `network.proxy` 默认空（直连国内数据源）。只有你的网络必须走代理时才填，例如 `http://127.0.0.1:7890`（按你的代理软件实际端口修改）。

## 5. 微信推送

### Server酱

1. 打开 <https://sct.ftqq.com/>，微信扫码登录，复制 SendKey。
2. 在 `config.json` 填：

```json
"push": { "enabled": true, "provider": "serverchan", "serverchan_key": "SCTxxxxx" }
```

3. 测试：`python fund.py push-test`

### PushPlus

1. 打开 <https://www.pushplus.plus/>，微信扫码，复制 token。
2. 配置：

```json
"push": { "enabled": true, "provider": "pushplus", "pushplus_token": "xxxxx" }
```

3. 测试：`python fund.py push-test`

推送策略：

- 只有出现**新的**买入/T1/T2/T3 信号才即时推送；
- 每周五运行后额外推一份周报；
- `check --dry-run` 只打印、不发送；
- 推送失败会记到 `logs/push_failures.jsonl`，不影响报告生成。

### 每天推指数星级

在 `config.json` 把 `run.index_watch_push` 改成 `true`，并启用 `push`。之后每天 21:30 的定时任务会推送：

```
指数星级｜2026-10-22 中证800 4.36★

| 指数 | 今日 | 修正星级 | 估值星级 | 价格星级 | 全历史分位 | 3年回撤 | PE | PB | 状态 |
...
- 中证800：4.36 星。成分估值星级需 ≥4.8（现在 4.36）；价格需 ≤4220（现在 4482，+6.2%）。
```

只想手动看/手动推一次：

```bash
python index_watch.py                 # 终端打印（用本地缓存）
python index_watch.py --refresh       # 先联网刷新估值，再打印
python index_watch.py --json          # JSON
python index_watch.py --push          # 立即推一次
```

## 6. 公众号文章

微信公众号没有可靠的公开抓取接口，所以采用“你给链接，脚本解析”的半自动方式：

```bash
python fund.py article https://mp.weixin.qq.com/s/xxxxx
```

或者把多条链接粘进 `articles/inbox.txt`（每行一条），然后：

```bash
python fund.py article --inbox
```

脚本会：

1. 抓取文章正文、标题、发布时间；
2. 识别市场星级（如“4.3 星”，按 5 星最便宜的螺丝钉口径）；
3. 尝试解析文章里的 HTML 估值表格，匹配到蛋卷指数后写入 `data/valuation_overrides.json`；
4. 把文章归档到 `articles/`。

**重要限制**：螺丝钉等公众号的估值表经常是**图片**。纯标准库无法 OCR。遇到图片表格时脚本会明确提示，不会编造数据。两种补录方式：

- 手动编辑 `data/valuation_overrides.json`（格式见下）；
- 把截图里的数字发给我，我帮你写进去。

手动补录格式：

```json
{
  "market_star": { "value": 4.3, "date": "2026-10-20", "source": "手动" },
  "indices": {
    "SZ399997": {
      "name": "中证白酒",
      "pe_pct": 0.21,
      "pb_pct": 0.03,
      "level": "low",
      "date": "2026-10-20",
      "source": "公众号"
    }
  }
}
```

估值覆盖 7 天内有效（`article_max_age_days`），过期后面板会回到蛋卷数据。

## 7. 面板与报告

- `reports/dashboard.html`：自包含面板，内联 CSS + SVG，无外部 CDN；手机/桌面都能看。
- `reports/latest.md`：当日文字摘要。
- `reports/weekly-YYYY-Www.md`：每周五自动生成。
- `docs/index.html`：指数星级静态页，含中证800/中证500/沪深300/全市场估值，不含个人持仓，可直接放 GitHub Pages。
- `data/history.jsonl`：所有历史信号，可用来复盘“当时为什么提醒”。

面板每张卡片显示：最新净值/日涨跌、估值分位条、距 250 日高点、距高估区峰值、晨星评级、止盈阈值、当前动作、250 日走势。

## 8. 每天自动更新：GitHub Actions（不用本地电脑）

仓库自带 `.github/workflows/update-index.yml`。每个工作日运行三次（北京时间）：

| 时间 | UTC cron | 用途 |
|---|---|---|
| 11:35 | `35 3 * * 1-5` | 午盘看一眼：上午跌到买点，下午还能操作 |
| 15:05 | `5 7 * * 1-5` | 收盘后立刻出当日结果 |
| 18:05 | `5 10 * * 1-5` | 固定推一条简报（关键数字 + 网页链接） |
| 21:35 | `35 13 * * 1-5` | 官方估值更新后复核 |

每次 GitHub 的服务器会自动：

1. 检出仓库；
2. 运行 `python index_watch.py --refresh --html docs/index.html`；
3. 从东方财富/腾讯取中证800/中证500/沪深300 最新点位，按当日涨跌推算盘中 PE/PB、回撤和星级；
4. 如果页面有变化，自动提交并推回 `main`，GitHub Pages 随后更新。

页面内容：

- 每个指数一行的**今日涨跌幅**（红涨绿跌）；
- 修正星级、估值星级、价格星级、全历史分位、3 年回撤、PE、PB；
- **近 1 周 / 近 1 月 / 近 1 年**涨跌幅和小走势图；
- 直接写明 v3.2 当前动作：4.8★ 建仓（首笔按回撤深度 1/3、1/2 或 2/3）、加第二/三笔、V 型底补仓、崩盘过滤暂停加仓、卖出 1/3、卖出剩余 2/3、强趋势移动止盈或保险清仓；不买时给出距离 4.8 星的估值和价格差。

15:00 前运行显示“盘中估算”，15:00 后显示“收盘估算”；晚间的官方数据才是最终值，页面上会标明。

不需要自己的服务器，也不需要本地定时任务。`data/cache/` 里的历史估值作为基线提交在仓库里，每天刷新后的数据用 Actions 缓存保存，不会把仓库撑大。

首次启用时：

1. 仓库 **Settings → Actions → General → Workflow permissions**，选 **Read and write permissions**，保存。否则 Action 没有权限把 `docs/index.html` 推回去。
2. 仓库 **Actions** 标签 → 左侧 **Update index star page** → **Run workflow**，先手动跑一次确认。
3. 之后每个工作日自动运行。GitHub 的定时任务可能延迟几分钟到二十分钟：15:05 那次实际可能 15:10–15:30 才出页面。

也可以随时在 Actions 页面点 **Run workflow** 手动刷新。

### 8.0 买卖信号推送到微信 / 邮箱

不用每天看网页，出现**新的**买/卖档位时让 GitHub Actions 主动提醒。触发条件（与线上 v3.2 一致）：

- 修正星级 ≥4.8（T1 建仓，首笔按 1 年回撤深度决定 1/3、1/2 或 2/3）；
- 价格 ≤T1×0.90 / ≤T1×0.80，或趋势确认条件满足（T2/T3 加仓）；浅 V 底在 T1 后 60 天站上年线 8% 也会补第二笔；
- 全历史分位 ≥60% / ≥63%（S1 卖 1/3、S2 卖剩余）；
- 强趋势中剩余仓位转 12% 移动止盈（含触发清仓）；
- 最大浮盈 ≥40% 后从本轮高点回撤 10% 且年线向上（保险清仓）。

同一档位只提醒一次；信号消失后（比如又涨回去）会自动复位，下次重新触发再提醒。所以不会在熊市底部每天刷屏。

#### 最省事：GitHub Issue → GitHub 邮件 → QQ 邮箱（默认，不需要任何 Secret）

不用注册第三方服务，也不用关注陌生公众号，只用你已有的 GitHub + QQ 邮箱：

1. **确认 GitHub 账号绑定了 QQ 邮箱**：GitHub → **Settings → Emails**，添加并验证 QQ 邮箱，设为 Primary。
2. **打开邮件通知**：GitHub → **Settings → Notifications → Email**，保持 Issues 的 “Participating, @mentions and custom” 开启（默认就是开的）。
3. 等下一次 Action 运行（或手动 Run workflow）。它会在仓库里创建一个 issue **「指数星级提醒（自动）」**，把你设为 assignee 并 @你；以后每天的提醒都追加在同一个 issue 里，不会建一堆。
4. GitHub 会发邮件到 `notifications@github.com` 对应的 QQ 邮箱。第一次可能在垃圾箱，把它加入白名单；然后在微信里开启 **QQ邮箱提醒**，就能从微信收到。

如果 GitHub 邮件慢，也可以装 GitHub 手机 App，打开 Issues 推送，比邮件更快。

#### 其他方式（需要额外配置）

| 方式 | 需要的配置 | 说明 |
|---|---|---|
| Server酱 | `SERVERCHAN_KEY` Secret | 微信直推最快，但要注册 sct.ftqq.com 并关注“方糖”服务号 |
| PushPlus | `PUSHPLUS_TOKEN` Secret | 微信直推，同样要注册第三方 |
| 邮箱 SMTP | `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `MAIL_TO` | 不经过 GitHub，直接发 QQ 邮箱；需要 SMTP 授权码 |

默认走 GitHub Issue；想换方式，在仓库 **Settings → Secrets and variables → Actions → Variables** 加一个 `PUSH_PROVIDER`，值为 `serverchan` / `pushplus` / `email` / `github_issue`。

本地想测试推送，可以临时设置环境变量后运行：

```bash
python index_watch.py --push --daily         # 每天一次，15:00 后才会发
python index_watch.py --push --signal-only   # 只在新信号时推
```

推送状态存在 `data/alert_state.json`，由 Action 自动提交；不需要手动维护。

## 9. 回测

用历史净值回放同一套止盈纪律，看看“上次高点会不会跑掉”：

```bash
python fund.py backtest 161725 --start 2020-07-01 --end 2022-12-31
```

输出会列出每次 T1/T2/T3 的日期、净值、分位、距 250 日高点，以及策略与买入持有的最终净值和最大回撤。

注意：历史指数估值不可得，回测只能用净值位置（3 年分位 ≥90% 且距 250 日高点 ≤5%）模拟“进入高估区”，不是历史 PE 百分位。所以回测结果用于验证**止盈纪律**，不能当作收益预测。

示例（161725，2020-07 到 2022-12）：

```
2020-07-01  T1  净值 2.3755  3年分位 100%  距250日高点 0.0%  减仓 1/3
2020-07-02  T2  净值 2.4189  3年分位 100%  距250日高点 0.0%  再减 1/3
2021-03-02  T3  净值 2.9026  3年分位 94%   距250日高点 -10.7% 卖出剩余
策略最终净值 2.5657（买入持有 1.2075）
策略最大回撤 -4.3%（买入持有 -20.5%）
```

### 9.1 用真实指数估值按完整牛熊周期回测

`fund.py backtest` 用的是基金净值分位，抓不到“2021 年价格到顶、但 PE 因盈利暴增而显得便宜”这种情况。`cycle_backtest.py` 改用中证500真实 PE/PB 分位（`data/cache/zz500_history.json`），按“熊底 → 牛顶 → 熊底”分段回测：

```bash
# 第 1 轮：2018-12-28 熊底 -> 2024-02-05 熊底（中间是 2021-09-13 牛顶）
python cycle_backtest.py --start 2018-12-28 --end 2024-02-05

# 第 2 轮：2024-02-05 熊底 -> 2026-10-21 当前（中间是 2026-06-30 牛顶）
python cycle_backtest.py --start 2024-02-05 --end 2026-10-21 \
    --t1 0.60 --t2 0.68 --trail 0.12 --price-stop 0.20 --window all

# 参数网格
python cycle_backtest.py --start 2024-02-05 --end 2026-10-21 --grid --window all

# 联网刷新中证500估值历史后再跑
python cycle_backtest.py --refresh --start 2024-02-05 --end 2026-10-21
```

参数说明：

| 参数 | 含义 |
|---|---|
| `--window 5/10/all` | 分位回看窗口。默认 10 年；`all` 是 2007 年以来全历史 |
| `--t1 / --t2` | 第一、二档止盈分位（0.60 = 60%） |
| `--trail` | T1 之后从高点回撤多少清掉剩余仓位 |
| `--price-stop` | T1 之前从本轮最高点回撤多少直接清仓；`0.20` = 20% |
| `--grid` | 打印多组 T1/T2/尾随/价停的对比 |

为什么要区分窗口：10 年滚动窗口会把 2015 年泡沫逐年移出样本，同样的绝对 PE 在 2025 年后会被算得“更贵”。同一个估值位置，10 年窗口的 80/90% 大约对应全历史的 60/68%。**阈值必须和窗口配套，不能拿 10 年窗口的 60% 去套全历史。**

### 9.2 中证800 / 全市场 / 指数星级

`cycle_backtest.py` 也支持中证800和全市场：

```bash
python cycle_backtest.py --latest --index zz800      # 中证800（合成）
python cycle_backtest.py --latest --index zz500 --code 161017
python cycle_backtest.py --latest --index hs300      # 沪深300
python cycle_backtest.py --latest --index market     # 全市场平均 PE/PB
```

中证800没有现成估值接口，用 **75% 沪深300 + 25% 中证500** 按市值权重合成：

- PE/PB 用调和加权（盈利/净资产加权）：`PE800 = 1 / (0.75/PE300 + 0.25/PE500)`；
- 价格用日收益加权，用于计算 3 年回撤和回测；
- 估值星级不混合 PE/PB 水平，而是 `0.75*沪深300估值星级 + 0.25*中证500估值星级`；
- `--weight-hs300 0.70/0.80` 可做敏感性检查。

修正星级的完整定义见 1.1。输出示例（2026-10-22）：

```text
中证800：PE 13.90  PB 1.49
  全历史分位 37.7%（10 年分位 48.7%）
  估值星级 4.19 ｜ 价格星级 4.49（3 年高点 2727，现价 2189，-19.7%）
  修正星级 4.19 → 等待区，新资金不买
全市场估值星级 3.92（仅参考）
```

**注意**：指数修正星级不是螺丝钉的官方市场星级，数字不能直接对比。螺丝钉星级是全市场温度计；单只指数必须用它自己的估值分位和价格回撤。2021 年中证500 价格到顶时 PE 分位只有 20–25%，只看估值仍会显示“便宜”，所以新规则用价格星级把 4.8 星门槛推到“较 3 年高点 -26%”。

### 9.3 三指数全历史验证（v3.2）

`rule_validation.py` 用真实历史数据逐日模拟：200k 初始资金、盈利滚入下一轮、不计交易费用。下表同时给出“空仓现金 0 收益”的保守口径和“空仓放货币基金、按 1.5%/年计息”的现实口径。历史缓存随仓库提供：

```bash
python rule_validation.py --v3                    # 三个指数全历史
python rule_validation.py --v3 --index zz500      # 单看一个指数
python rule_validation.py --v3 --cash-rate 0.015  # 空仓现金按 1.5% 货币基金计息
python rule_validation.py --v3 --json             # JSON 摘要
```

200k 初始资金、复利滚动的结果：

| 指数 | 区间 | 现行规则 | **v3.2（现金 0%）** | **v3.2（现金 1.5%）** | 买入持有 |
|---|---|---:|---:|---:|---:|
| 中证500 | 2007-01 → 2026-10 | 82.0万（7.4%/年） | **145.9万（10.6%/年）** | **164.9万（11.3%/年）** | 68.9万（6.5%/年） |
| 中证800 | 2007-01 → 2026-10 | 57.2万（5.5%/年） | **136.8万（10.2%/年）** | **159.4万（11.1%/年）** | 43.8万（4.0%/年） |
| 沪深300 | 2005-04 → 2026-10 | 63.2万（5.5%/年） | **127.7万（9.0%/年）** | **148.7万（9.8%/年）** | 82.0万（6.8%/年） |

- “现金 1.5%”指空仓资金放货币基金、按年化 1.5% 计息；不改变任何买卖信号。
- 13 轮真实 4.8★ 买入中，按账户资金算平均 **+59.0%**、中位 **+44.1%**；按实际投入资金算平均 **+59.9%**、中位 **+44.1%**，11/13 超过 +30%。空仓计息后平均 **+60.1%**、中位 **+45.5%**，最差一轮也从 +23.5% 提高到 +24.1%。
- 最大回撤：现金 0% 口径 -30.0% / -27.9% / -25.6%，现金 1.5% 口径 -27.8% / -24.8% / -24.7%，都远低于买入持有的 -72%。
- v3.2 的 V 型底补仓只改变沪深300 2018 那一轮：账户收益 +18.8% → +35.9%，期末 111.5万 → 127.6万；代价是这一轮从 33% 仓位变成满仓，投入收益 +56.5% → +35.9%，单轮回撤 -6.3% → -16.1%。
- 崩盘过滤主要改善中证500 的 2008 年：那一轮 +22.7% → +44.1%；对中证800 反而偏保守（2018 年 +47.1% → +33.8%），对沪深300 基本不变。保留统一规则，是因为中证500 的改善大于中证800 的让利。
- 已知弱点：中证500 在 2016 年最高只有 3.89★，整轮空仓；2008 年首笔仍在下跌前段，最大回撤 -30%。中证800 修正星级后 2008-10 才建仓，回撤降到 -27.9%。靠“只用计划资金、不加杠杆”控制尾部损失。

`strategy_backtest.py` 仍保留为按固定周期、每轮固定 20 万的旧规则对照工具，不再代表线上 v3.2。

## 10. 数据源与容错

| 数据 | 来源 |
|---|---|
| 净值历史、基金名称 | 天天基金 `pingzhongdata` |
| 基金类型、跟踪标的 | 天天基金基金档案 |
| 晨星/招商/济安评级 | 天天基金 F10 评级接口 |
| 指数 PE/PB 百分位 | 蛋卷 `index_eva` |
| 中证500历史 PE/PB（回测） | `harryblog.site/api/zz500_data`（乐咕口径，缓存为 `data/cache/zz500_history.json`） |
| 沪深300历史 PE/PB（回测） | `harryblog.site/api/hs300_data`（缓存为 `data/cache/hs300_history.json`） |
| 全市场平均 PE/PB | `harryblog.site/api/average_pe_data`（缓存为 `data/cache/market_history.json`） |
| 指数实时点位 | 东方财富行情（仅沪深指数） |

- 所有请求带 UA、gzip、重试和磁盘缓存；单个基金失败不会影响其他基金。
- `--offline` 只用缓存，适合断网时复看。
- 天天基金的移动基础接口会拦截 Python TLS 指纹，工具已改为不依赖它（用档案页 + 净值历史）。
- 数据源接口可能变更；如果大面积失败，先看 `logs/fund.log` 和 `data/cache/`。

## 11. 常见问题

**Q：为什么某只基金显示“无估值数据”？**
蛋卷只覆盖 63 个指数，小众主题/行业基金可能匹配不到。工具会降级为净值位置信号。可以在 `config.json` 手动填 `index_code`，或用 `article` 从公众号表格补录。

**Q：为什么低估值没有每天提醒？**
买入信号有 10 天冷却，卖出档位有 5 天冷却，避免消息疲劳。状态在 `data/state.json`。

**Q：为什么卖出后一直不重新买入？**
需要估值/净值分位回落到 70% 以下并持续 5 个交易日，且距上次峰值至少 -8%。可在 `config.json` 调 `rearm_val_pct` / `rearm_days` / `rearm_drawdown`。

**Q：能自动下单吗？**
不能。工具不接券商，不做交易。所有操作需要你手动执行。

**Q：数据准吗？**
净值/评级来自天天基金，估值来自蛋卷，均为公开数据；可能有延迟、缺失或口径差异。估值百分位是历史统计，不代表未来。
